## Project Overview

**Postloom** (codebase name: `x_studio`) is a social media management and tweet card generator app. It allows users to design social media cards (tweet cards, Instagram posts, LinkedIn graphics, animated GIFs), manage drafts, schedule posts, connect social accounts, and use AI-powered content generation.

## Commands

Always use `bun` (never npm or pnpm) per project rules.

```bash
bun install           # Install dependencies
bun run dev           # Dev server on port 4000
bun run build         # Production build
bun run test          # Run all tests (vitest)
bun run lint          # ESLint
bun run format        # Prettier
bun run check         # Prettier + ESLint fix (format + lint together)
bun run db:migrate    # Run DB migrations via scripts/migrate.ts
bun run deploy        # Migrate + build + wrangler deploy to Cloudflare
```

Run a single test file:

```bash
bunx vitest run src/path/to/file.test.ts
```

Add Shadcn components:

```bash
bunx shadcn@latest add button
```

## Architecture

### Framework & Routing

TanStack Start (SSR-capable React framework) with file-based routing. Routes live in `src/routes/`. The generated route tree is at `src/routeTree.gen.ts` — do not edit it manually, it's auto-generated by the TanStack Router plugin on dev/build.

- `src/routes/__root.tsx` — root layout: wraps all routes with TRPC provider, Neon auth, and Toaster
- `src/routes/_app/` — authenticated app shell (dashboard, drafts, posts, schedule, analytics, radar, accounts, templates)
- `src/routes/tweet-card-generator/` — the public card generator tool (no auth required)
- `src/routes/auth/` — auth pages (sign-in, sign-up via Neon Auth)
- `src/routes/api.trpc.$.tsx` — tRPC HTTP handler endpoint
- `src/routes/api.cron.tsx` — Cloudflare cron trigger handler
- `src/routes/api.oauth.$platform.callback.tsx` — OAuth callback for social platforms

### API Layer (tRPC)

tRPC v11 with superjson transformer. All API logic flows through:

- `src/integrations/trpc/init.ts` — tRPC initialization, context creation, `publicProcedure` and `protectedProcedure`
- `src/integrations/trpc/router.ts` — root router combining all sub-routers
- `src/integrations/trpc/routers/` — individual routers: `socialAccounts`, `drafts`, `templates`, `posts`, `schedule`, `analytics`, `oauth`, `ai`, `radar`

`protectedProcedure` enforces auth via `getSession()` from `src/lib/auth.ts`. On the client, `Authorization: Bearer <token>` is injected via `src/integrations/tanstack-query/root-provider.tsx` with 60s caching.

### Auth

Neon Auth (`@neondatabase/neon-js`) with Google OAuth provider. The `authClient` from `src/lib/auth.ts` is used throughout. `NeonAuthUIProvider` wraps the app in `__root.tsx` with `redirectTo="/dashboard"`.

### Database

Neon Postgres (`@neondatabase/serverless`). Schema defined in `db/init.sql`. Tables: `social_accounts`, `drafts`, `templates`, `scheduled_posts`, `published_posts`, `analytics_events`. Migration runs via `bun run db:migrate`.

### State Management

- **Server state**: TanStack Query + tRPC (query invalidation pattern)
- **Client state**: Zustand (`zustand`) for the card generator editor state
- **TanStack Store** available for derived/reactive state

### Environment Variables

Managed via `@t3-oss/env-core` in `src/env.ts`. Access as `import { env } from '@/env'`.

- `VITE_`* prefix = client-side (exposed to browser)
- No prefix = server-side only
- Key vars: `DATABASE_URL`, `X_CLIENT_ID/SECRET`, `LINKEDIN_CLIENT_ID/SECRET`, `THREADS_APP_ID/SECRET`, `VITE_GA4_MEASUREMENT_ID`, `VITE_CF_BEACON_TOKEN`

### Deployment

Cloudflare Workers via Wrangler. Config in `wrangler.jsonc`. The `bun run deploy` command runs migrations, builds, then deploys. See `DEPLOYMENT.md` for full Cloudflare setup instructions.

### UI Components

Shadcn/ui components in `src/components/ui/`. Tailwind CSS v4. Icons from `lucide-react`. Animations via `framer-motion`. Toast notifications via `sonner`.

### Path Aliases

`@/` maps to `src/` (configured via `vite-tsconfig-paths`).
